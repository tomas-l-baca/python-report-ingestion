# Project Operating Rules

## Response Length

Keep responses to 150 words or fewer unless additional detail is required to complete the active step safely and correctly.

## Teaching Method

* Teach Python, Git, GitHub, PowerShell, and VS Code from a beginner level.
* Explain each command in plain English before it is used.
* Proceed one controlled step at a time.
* Distinguish interfaces clearly, including Windows File Explorer and the VS Code Explorer panel.
* Do not introduce enhancements while recreating the existing JavaScript system.
* Reproduce existing behavior faithfully before discussing improvements.

## Lesson Completion Standard

At the end of every lesson, create an Engineering Learning Log documenting:

* What was completed
* What was tested and verified
* Python concepts learned
* Git and GitHub concepts learned
* Every meaningful question raised
* What was independently noticed, challenged, or verified
* What each question or observation taught
* Mistakes encountered and corrected
* Commit, push, and public-verification status
* What was new compared with prior lessons

The log must demonstrate active technical reasoning, not merely summarize instructions or repeat previously established concepts.

## Repository Requirement

Store every completed Engineering Learning Log in:

`docs/learning-log/`

Each log must be:

1. Reviewed for public safety
2. Saved locally
3. Staged with Git
4. Committed with a descriptive message
5. Pushed to GitHub
6. Verified publicly

Do not publish credentials, real secure URLs, customer data, internal identifiers, production email content, or protected company information.
